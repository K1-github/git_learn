# レッスン5: プルリクエスト (PR) 🙌

**プルリクエスト（Pull Request, PR）** は
「私のブランチの変更を、あなたのブランチ（例: main）に取り込んでください」という **提案** です。

GitHub 上で行う操作で、Git そのものの機能ではなく GitHub の機能です。

## PR の一生（ライフサイクル）

```
1. ブランチで作業してコミット
2. push で GitHub に上げる
3. PR を作成（変更内容を説明）
4. 他の人がレビュー・コメント
5. 必要なら修正して再度 push（PRに自動反映される）
6. 承認されたら Merge（本流に合流）
7. ブランチを削除して完了
```

## PR に書くとよいこと
- **何を** 変えたか（概要）
- **なぜ** 変えたか（背景・目的）
- 確認方法やスクリーンショット（あれば）

## PR の作り方（2通り）

### A) GitHub の画面で作る
1. push した後、GitHub のリポジトリページを開く
2. 「Compare & pull request」ボタンが出るので押す
3. タイトルと説明を書いて「Create pull request」

### B) この Claude Code 環境で頼む
Claude に「この変更でプルリクエストを作って」と頼めば作成できます。
（作成は明示的に頼まれたときだけ行います）

## レビューへの対応
- コメントで修正を求められたら、同じブランチで直して `git commit` → `git push`
- push するだけで PR は自動で最新になります（新しく作り直す必要はない）

## Merge の種類（ざっくり）
- **Merge commit**: 履歴をそのまま残して合流
- **Squash merge**: 複数コミットを1つにまとめて合流（履歴がきれい）
- **Rebase merge**: 一直線の履歴にして合流

最初は違いを気にせず「Merge」で大丈夫です。

## 🛠️ やってみよう
1. これまでのレッスンの変更を push 済みにする（レッスン3参照）
2. GitHub でこのブランチの PR を作ってみる
   （または Claude に「PRを作って」と依頼）
3. PR の説明欄に「何を学んだか」を書いてみる
4. 自分の PR を眺めて、Files changed タブで差分を確認する

🎓 ここまでできれば、Git の基本サイクルは一通り体験完了です！

## もっと学ぶには
- `git revert` … 特定のコミットを打ち消す
- `git stash` … 作業を一時退避する
- コンフリクト解消 … 同じ行を別々に変えたときの対処
- `git rebase` … 履歴を整理する
